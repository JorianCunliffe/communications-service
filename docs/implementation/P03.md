## Contract and scope (P03.2 / P03.4)

Communications `POST /v1/context/memory` accepts `kind` (`search`, `person`, `thread`, `project`, `meeting`, `loose_ends`), an `id` where applicable, query and narrowing scope. Response is `memory-context.v1` with `data` and `memory_status` (`current` or `stale`, retrieval timestamp, evidence-only flag). Missing/inaccessible context returns 404; retrieval failure returns 503. A successful bounded empty result is different from either error.

HyperFlow `POST /api/communications/memory` accepts the same view kinds plus `projectId` and `personId`. Tenant comes exclusively from verified membership. Accessible projects come from HyperFlow's organization project lookup, never a client-supplied grant list. HyperFlow project IDs map to `external_project_id` search; Communications internal project UUIDs remain distinct. Browser credentials and service keys are never exchanged with each other.

The panel in Settings supports person, thread, project, meeting, search and loose ends. It fetches on demand, clears on scope/account changes, cancels obsolete responses and displays source references/excerpts. It distinguishes missing, unavailable, withheld/stale and bounded empty results. It never creates an Ask or marks a promise kept.

Communications rechecks current canonical rows for eligibility, private/restricted metadata, person/project/thread/meeting scope, time/channel filters and newer source edits. Facts/promises/summaries require valid source IDs in their current thread. Retractions/supersession and failed/voicemail/automated sources cannot supply trusted evidence. Shared-thread labels and participant details without eligible source support are withheld. Summary provenance is validated before both nested and top-level copies are returned.

Meeting context uses explicitly linked meeting communications, including transcripts ingested after the meeting started. It does not widen into every participant's unrelated history. Ask loose ends require an eligible scoped communication bound to that Ask; operational Ask state stays distinguishable from extracted promises.

## Promise dates (P03.3)

Original source wording is returned as `original_wording`; source IDs and a bounded source excerpt are retained. A derived due date becomes `due_at_candidate`, with `due_date_status: inferred` and confirmation required. `due_at` is retained only when a matching timezone-bearing timestamp appears explicitly in the source. Ordinary weekdays/date-only wording are conservatively uncertain because their date/time/zone interpretation may be assumed. Stored historical dates are not rewritten; no business deadline or fulfillment is automatically confirmed.

## Assumptions and limits

1. Current HyperFlow membership grants access to organization projects. Phase 03 adds narrowing; it does not invent a finer project ACL. The existing external-person/voice grant path remains unchanged and does not automatically receive this memory.
2. HyperFlow always excludes private/restricted evidence, even for an owner. It excludes sources without a recognized accessible external project. A future explicit mailbox/source-grant model is needed to broaden that safely. Communications service clients are tenant-level principals; request filters narrow their authority and are not an independent end-user grant system. `include_private: true` requires the additional `memory:private` capability there.
3. Privacy depends on the existing source metadata being correctly classified. This is not a new mailbox visibility migration or classification backfill. Do not claim protection for private content incorrectly marked public.
4. Results are bounded and filtering may yield fewer results. An empty page does not establish absence across all history. `current` means returned evidence passed these checks, not that all enrichment jobs are done or every source has been ingested.
5. Freshness uses existing source timestamps/thread membership and an enrichment evidence horizon. It is conservative and is not an atomic database snapshot or a claim of production multi-node race verification. Old rows without complete citations are suppressed; no historical backfill was performed.
6. Contact and meeting references use existing canonical IDs; automatic self-contact mapping, meeting-provider import expansion and a complete obligations UI are later work. Evidence excerpts are bounded to 4,000 characters; full raw communications remain under Communications' existing authenticated API.
7. Raw register/history APIs keep their existing tenant service authority. This scoped context adapter does not turn those unrelated APIs into per-source ACL endpoints.
