# Phase 11 — Communications tenant operations

Status: first tenant API release live; Phase 11 remains in progress. HyperFlow owns its separate API clients and business stores. Existing memory stays in Communications.

Local migration 024 adds expiry/revision and managed-tenant metadata to existing hashed API clients, plus a server-only tenant administration audit. The lifecycle RPC atomically creates/rotates/revokes a single-tenant managed credential and records its actor. Original creation and identical rotation replay without another revision or audit entry. Legacy and multi-tenant operator credentials are excluded from this customer-facing lifecycle. The SQL uses security invoker, revokes PUBLIC execution, enables audit RLS and grants only the server role. The migration was created with the Supabase CLI then renamed for this repository's ordered runner; it has not been applied to production.

GET/POST /v1/tenant/clients requires administrator role and tenant:manage capability in addition to the existing read/write capability boundary. Creation may delegate only supported capabilities held by the caller. Clients supply a high-entropy secret; no plaintext secret or hash is returned. List pagination uses a stable key cursor. GET /v1/tenant/audit returns scoped administration history. Authentication rejects expired or revoked credentials.

The real Fastify/PGlite test passes for concurrent replay, redaction, read-only client restrictions, cross-tenant rejection, conflicting identity, rotation/old-secret invalidation, stale revision, expiry, idempotent revocation and atomic audit records. PUBLIC cannot execute the management function. These are isolated fixtures, not production credential changes.

Also implemented: atomic daily managed-client request budgets across both API surfaces, recoverable exempt administration endpoints, scoped usage history, a standalone origin/tenant-pinned JavaScript client and an OpenAPI supplement. The supplement covers this release, not every older endpoint. The usage API shows 90 days; database history is not automatically erased.

Remaining: whole-product API inventory/contracts, operational health, tenant lifecycle/export/deletion/retention receipts and recovery verification. Run full suites, migration checks and independent release verification before acceptance. No Phase 11 completion or live rollout is claimed.

First-release local checks: 263 unit tests and 36 PostgreSQL-backed tests passed. Migration coverage now expects 25 ordered migrations (000–024). Production deployment and post-release verification remain pending.

Dependency audit remediation: compatible Fastify 5.12.3, fast-uri 3.1.7/4.1.4 and qs 6.16.0 are locked. After restoring development dependencies, all 263 unit and 36 database tests pass and production audit reports zero vulnerabilities. The existing Svix 2.1.0 contract pin is preserved.
