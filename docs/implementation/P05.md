# Phase 05 — Already-transcribed meetings

Implementation prepared for release 2.5.0; production acceptance pending.

Communications owns the source manifest, immutable revision receipts, topic recordings, canonical contact enrichment, thread associations and existing memory enrichment. Migration 022 extends recordings rather than introducing a memory application. HyperFlow owns the authenticated review UI and operational commitment/Ask acceptance.

Generic JSON/text upload is the first adapter. Provider source IDs and versions are supplied by the caller; source and recording URLs are references, never fetch targets. No automatic Plaud/Fathom collection is claimed. Exact existing contact identities enrich attendees, while transcript speaker attribution remains a producer claim. Unresolved owners must be clarified in HyperFlow.

Each topic has a stable identity, project and independent thread. Imports and corrections are transactional under a tenant lock. Provider-version receipts prevent retry duplicates; matching content across provider IDs requires explicit separate-meeting review. Corrections preserve communication IDs and thread correction history. Removed topics become ineligible evidence. Revision history is retained. Existing accepted HyperFlow obligations are not rewritten by source changes.

Validation: 262 unit tests and 33 PostgreSQL-backed tests pass, including the full 000–022 migration sequence. The meeting story proves two-topic isolation, exact/unknown identities, source labels, deterministic promise extraction and retry deduplication, correction reconciliation, source-version conflicts, cross-project denial, tenant isolation, RLS/security-invoker shape and zero outbound operations. HyperFlow's separate HTTP/SQL integration proves candidate clarification and explicit acceptance followed by a source correction without changing accepted terms.

Release: merge reviewed code, preserve any hosted checkout differences, install dependencies and apply ordered migrations through the existing production startup. Verify the 2.5.0 build and authenticated source import, retry, enrichment and UI review before claiming live acceptance. Roll back the consumer first if required; retain additive tables and source receipts. No destructive rollback migration.

Limits: this fingerprint detects equal normalized content, not fuzzy semantic duplicates; project/thread metadata participates in it. Meetings spanning inaccessible projects are excluded as a whole. Private imports remain available only to specifically capable Communications clients; HyperFlow's initial UI declines them until a source grant exists. This is not inferred speaker verification or automatic commitment acceptance.
