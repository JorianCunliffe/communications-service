### Final behavior

- Explicit canonical thread and Ask binding precede ranked inference; conflicting bindings reject. Native email conversation IDs remain mailbox-scoped source references.
- Ambiguous ranking creates a separate unbound thread with a recorded decision, rather than attaching to a possible Ask. Ranking is a bounded lexical heuristic, not an LLM probability.
- Canonical register, candidate, correction and edit APIs are consumed by HyperFlow Settings. Register fetch is on demand; status/person/project filtering, 100-thread pages and 20-communication history pages are supported. Text search searches the loaded page.
- Manual corrections move only the selected communication and repair its relevant provider projection/reply route. Reason and actor provenance are retained. Corrections do not send, replay events or resolve an Ask.
- HyperFlow validates source/destination project references for writes against its organization projects. Communications enforces tenant ownership and internal project references. Explicit `wrong_project` is required for a cross-project move. Project changes on Ask/run/task-bound records reject; ordinary title/summary edits remain available.
- Actor audit stores JSON text with authenticated `client_id` and optional `user_id`. A service client may assert a user only with `threads:actor:assert` (or legacy wildcard). HyperFlow derives that user from verified membership. This is service-attested identity, not a second end-user authentication in Communications.
- Register component resets when organization changes. Older servers return a clear unavailable message, without writing alternate local thread state.
